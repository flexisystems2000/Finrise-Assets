FINRISE ASSET — PUBLIC FLOW FIXES

Completed in this build:
1. Public navigation: all known broken logI_Page.html/login.html/invest.html references were corrected.
2. Missing public image references were removed so pages no longer request missing logo/crypto files.
3. Referral signup: referral code is captured in Supabase Auth metadata and handle_new_user() creates the referral relationship automatically when the code matches a Finrise username-derived FR- code.
4. Investment availability: Starter, Silver, Gold and Platinum plans are active in public.investment_plans and match the dashboard investment buttons.
5. Withdrawal accounting: gross amount is the amount locked/debited; fee is stored; net_amount is stored as amount minus fee; completion releases the locked gross amount. The ledger does not double-count the fee.
6. Deposit payment details: fake/unverified bank and crypto destinations were removed. Deposit methods remain blocked until real payment destinations are configured in deposit.js PAYMENT_CONFIG. Do not publish or use unofficial addresses.
7. Settings: supported language/currency values are persisted; the wallet is NGN and unsupported currency/language options were removed. Theme and notification settings remain persisted through Supabase Auth metadata.
8. Profile pictures: a Supabase Storage bucket named finrise-avatars was created with per-user policies, and profile uploads are saved to the user's folder with the URL stored in Auth metadata.
9. Security: admin-only RPC execution was removed from anon/authenticated roles and restricted to service_role. User financial RPCs remain authenticated because the frontend legitimately calls them and they enforce auth/ownership checks.
10. Old localStorage dependency: no executable localStorage/sessionStorage calls remain in the audited public JS. Remaining mentions are comments only.

Important:
- Real bank/crypto payment details were intentionally NOT invented.
- Supabase Security Advisor will still warn about create_investment/create_withdrawal being SECURITY DEFINER because these authenticated user RPCs intentionally perform protected wallet mutations. They use a fixed search_path and explicit authenticated grants.
- Supabase Auth leaked-password protection still needs to be enabled from the Supabase Auth dashboard because it is not exposed by the available database migration interface.
- Admin system was not built or changed beyond hardening admin RPC grants, as requested.
